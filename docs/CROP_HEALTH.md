# Inspections and crop-health incidents — Web 0.5.0 local

The independently pinned Contracts 0.7.0 module adds /inspections and /incidents through Gateway. It records SIMULATED crop evidence and manual manager decisions. No automatic diagnosis or notification delivery is claimed. Existing estate administration, workforce and Cesium flows remain available.

Choose an estate, then Inspections or Incidents. Lists distinguish loading, empty, denied and failed requests. Filter by field, observation range and outcome/state or category/severity/status; default incidents show OPEN and IN_REVIEW. Use all statuses to include resolved/voided reports. Empty inspection results do not establish crop health. Times display in the selected estate timezone; input requires an explicit UTC offset.

Managers and supervisors may create reports using active fields; supervisors enter only today's estate-local observations. Managers must explain backdates. A CLEAR inspection saves evidence without an incident; FOLLOW_UP requires category/severity/summary/details and atomically creates its first linked incident. A direct incident creates no inspection. Detail screens link to the related report, preserving canonical UUIDs even if geometry is unavailable.

Managers can triage, amend, resolve with time/note, reopen, correct evidence or void through explicit flows. Auditors can read protected revision history; supervisors cannot read actors/revision reasons or change existing evidence. VOIDED is terminal. Inspection corrections retain identity/link and never silently close an incident. Void the linked incident first before clearing/voiding the inspection. Existing account and workforce identities are not linked or provisioned.

Each save freezes the submitted body and key in component memory. After an uncertain result, Retry identical submission reuses both; no silent duplicate or new key is generated. A 409 preserves the original draft/version and displays the current report for comparison. Discard and reload is explicit before revising. Dirty route changes require discard confirmation; the estate picker is disabled while a draft/pending result exists. Session/permission loss clears protected state. No report text/tokens are written to browser storage, traces with real credentials, console or analytics.

Only SIMULATED evidence is accepted. Do not enter worker names, personnel cases, actual plantation details, attachment URLs or sensitive personal information. II-D07/08 and WA D08/D09 remain open; REAL use and performance acceptance need their own approved evidence. Online one-report saves only, no offline/bulk/export flow.

This is local/unpublished source and packaging. Running the module against the existing local stack requires a separately authorized backend/Gateway/topology upgrade; fixtures are never copied into existing databases. Tests use mocked browser fixtures or independent generated disposable platform resources. Public image packaging uses scripts/build-public-image.ps1 and generated public defaults, excluding the owner's public/config.json and private environments. See Architecture verification/checkpoint for actual checks and remaining gates.
